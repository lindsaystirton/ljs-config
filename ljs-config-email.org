The mu4e/mbsync pilot discussed in the workflow doc -- now covering
both BIEN mailboxes, the internal one (the original pilot) and the
external Treasurer one, added once the pilot proved solid on two
machines. Everything here assumes the real-machine half is already
done for both accounts -- Homebrew's =mu= and =isync= installed,
=~/.mbsyncrc= with a Channel for each mailbox, both passwords added
to =~/.authinfo.gpg=, an initial =mbsync= sync of each, and =mu
index= run at least once -- none of which this file, or anything
else in this repo, can do for you.

The two actual email addresses are deliberately *not* written here.
This file is public, and a real email address is personal identity,
not shareable code -- so both addresses live in
=~/.emacs.d/ljs-config-private.el=, a small file that sits outside
this repo entirely (the same place =~/.mbsyncrc=, =~/.authinfo.gpg=,
and =~/Maildir= already live) and is never committed. See
=ljs-config-private.el.example=, alongside this file in the repo,
for the template anyone else cloning this config would fill in with
their own addresses.

* mu4e

mu4e isn't declared via straight.el like everything else in this
config -- deliberately. mu4e's elisp has to be the exact version
that shipped with the =mu= binary it talks to (a well-known mu4e
gotcha: a mismatched elisp/binary pair fails in confusing ways), so
rather than let straight pull an independent copy from its own
source, this loads whatever elisp Homebrew installed alongside the
=mu= binary itself, located dynamically via =brew --prefix mu=
rather than a hardcoded path -- the exact kind of hardcoded-personal-
path mistake already flagged elsewhere in this config (the audit,
item 2) is easy to avoid here for free.

#+name: ljs-config-email-load-path
#+begin_src emacs-lisp
(let ((mu-prefix (ignore-errors
                    (string-trim
                     (shell-command-to-string "brew --prefix mu 2>/dev/null")))))
  (when (and mu-prefix (not (string-empty-p mu-prefix))
             (file-directory-p mu-prefix))
    (add-to-list 'load-path
                 (expand-file-name "share/emacs/site-lisp/mu/mu4e" mu-prefix))))
#+end_src

Deliberately minimal still -- manual refresh only (no background
sync timer), no per-folder tuning beyond the basics. Two mailboxes
now, both under the same =~/Maildir= root as sibling directories
(=/bien-lindsay/= and =/bien-treasurer/=) -- exactly the shape the
original single-mailbox pilot was built to anticipate. Since two
mailboxes means two sets of folders and two send addresses, mu4e's
own =mu4e-contexts= mechanism does the picking: each context's
=:match-func= looks at which mailbox a message actually lives in
(its maildir path), and its =:vars= then supplies that mailbox's
folders, From address, and SMTP username -- the two addresses pulled
from the private file's variables via =bound-and-true-p= (nil, not
an error, if the private file hasn't been loaded), not written here
directly. Replying to a message auto-selects the right context;
composing new mail reuses whichever context is already active rather
than asking every time (=mu4e-compose-context-policy 'ask-if-none=).
The four folder names were confirmed against the real mailbox after
the first sync of each account (no correction needed either time),
so unlike the original pilot these aren't guesses.

#+name: ljs-config-email-mu4e
#+begin_src emacs-lisp
(use-package mu4e
  :straight nil
  :if (executable-find "mu")
  :defer t
  :bind (("C-c m" . mu4e))
  :custom
  (mu4e-maildir "~/Maildir")
  ;; Both channels in one invocation -- add a third name here if a
  ;; third BIEN-style mailbox is ever piloted the same way.
  (mu4e-get-mail-command "mbsync bien-lindsay bien-treasurer")
  (mu4e-update-interval nil)
  (mu4e-context-policy 'pick-first)
  (mu4e-compose-context-policy 'ask-if-none)
  :config
  (setq user-full-name "Lindsay Stirton")
  (setq mu4e-contexts
        (list
         (make-mu4e-context
          :name "Lindsay (internal)"
          :match-func
          (lambda (msg)
            (when msg
              (string-prefix-p "/bien-lindsay" (mu4e-message-field msg :maildir))))
          :vars `((user-mail-address  . ,(bound-and-true-p ljs-bien-lindsay-address))
                  (mu4e-drafts-folder . "/bien-lindsay/Drafts")
                  (mu4e-sent-folder   . "/bien-lindsay/Sent")
                  (mu4e-trash-folder  . "/bien-lindsay/Trash")
                  (mu4e-refile-folder . "/bien-lindsay/Archive")
                  (smtpmail-smtp-user . ,(bound-and-true-p ljs-bien-lindsay-address))))
         (make-mu4e-context
          :name "Treasurer (external)"
          :match-func
          (lambda (msg)
            (when msg
              (string-prefix-p "/bien-treasurer" (mu4e-message-field msg :maildir))))
          :vars `((user-mail-address  . ,(bound-and-true-p ljs-bien-treasurer-address))
                  (mu4e-drafts-folder . "/bien-treasurer/Drafts")
                  (mu4e-sent-folder   . "/bien-treasurer/Sent")
                  (mu4e-trash-folder  . "/bien-treasurer/Trash")
                  (mu4e-refile-folder . "/bien-treasurer/Archive")
                  (smtpmail-smtp-user . ,(bound-and-true-p ljs-bien-treasurer-address))))))
  ;; Sending, via Migadu's SMTP -- server, port, and stream type are
  ;; the same for both mailboxes (same host, same password scheme);
  ;; only smtpmail-smtp-user differs, which is why it lives in each
  ;; context's :vars above rather than here. Port 465 with direct
  ;; TLS rather than 587 + STARTTLS, for the same reason IMAP uses
  ;; 993. Composing stays plain text by default -- deliberately not
  ;; adding org-mime for HTML replies yet, per Lindsay's own call.
  (setq message-send-mail-function 'smtpmail-send-it
        smtpmail-smtp-server "smtp.migadu.com"
        smtpmail-smtp-service 465
        smtpmail-stream-type 'ssl)
  ;; Migadu doesn't auto-file a Sent copy the way some providers'
  ;; SMTP does -- mu4e saves its own copy into the active context's
  ;; mu4e-sent-folder after sending, which mbsync then carries back
  ;; up to the server on the next sync.
  (setq mu4e-sent-messages-behavior 'sent))
#+end_src
