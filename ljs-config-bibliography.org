#+TITLE: LJS Config Bibliography
#+OPTIONS: toc:nil H:2 num:nil ^:nil

This is part of the [[file:ljs-config.org][LJS-Config]]. Reference management for LaTeX
writing, built around Zotero rather than an Emacs-native bibliography
tool -- the design goal is a workflow that is fully keyboard-driven on
this end while staying compatible with co-authors who aren't using
Emacs, or LaTeX, at all.

* LJS Config Bibliography

** Architecture

The reference database itself lives in Zotero, not in a hand-managed
=.bib= file and not in ebib (which used to be configured in
=ljs-config-latex.org= and has been removed -- see the note there).
Zotero was chosen over an Emacs-native tool specifically because
co-authors need to be able to add and edit references too, and
essentially none of them will ever open Emacs: Zotero's group
libraries let everyone contribute from whatever editor or platform
they use, with a browser plugin for capturing references directly
from journals and databases.

The [[https://retorque.re/zotero-better-bibtex/][Better BibTeX]] Zotero plugin does the actual bridging to LaTeX. It
assigns stable citation keys -- so a key never changes just because an
item's metadata was edited, which matters once =\cite{key}= is
scattered through a document -- and keeps a =.bib= file on disk
continuously synced to the Zotero library, so nothing needs manually
exporting before compiling.

*** The OSCOLA complication: two bibliography files, not one

OSCOLA citation (=oscola-latex=, aka =biblatex-oscola= -- see
=ljs-config-latex.org=) defines its own BibLaTeX entry types for
primary legal sources: =@jurisdiction= for cases, =@legislation=, and
=@legal= for treaties and Hansard, each with bespoke fields for things
like neutral citations, reporters, and pagination-by-type. Zotero's
own "Case" and "Statute" item types don't map onto these -- Better
BibTeX exports them as generic =@misc= entries, which the oscola style
won't format correctly. This is a long-standing, acknowledged gap in
Zotero's BibTeX export, not something fixable from the Emacs side.

The practical answer is to split the bibliography in two rather than
force everything through Zotero:

- Secondary sources (articles, books, chapters) stay in the shared
  Zotero library, auto-exported by Better BibTeX as above. This is
  where collaborative editing actually matters, and it works cleanly.
- Cases and legislation go in a second, hand-authored =.bib= file
  written directly in oscola's own entry types. In practice this is
  little extra work: primary legal citations are usually typed in by
  whoever is drafting that section anyway, in any citation workflow,
  rather than pulled from a shared library.

Citar (below) is pointed at both files at once, so citation completion
in AUCTeX doesn't distinguish between them.

** Where the =.bib= files live

No path is hardcoded here, matching the ebib note this section
replaces in =ljs-config-latex.org=. =citar-bibliography= is left at
its default (nil) below -- it's set instead in your per-user override
file (=ljs46.org= or =ljs.org=, see the audit, §41), alongside the
matching =reftex-default-bibliography= fallback:

#+begin_src emacs-lisp :tangle no
(setq citar-bibliography
      (list "~/Dropbox/bibliography/Zotero.bib"  ; Better BibTeX auto-export from Zotero
            "~/Dropbox/bibliography/cases.bib")) ; hand-maintained oscola case/legislation entries
#+end_src

** Install and configure citar

Citar replaces ebib's old citation-insertion role, with fuzzy
completion that matches the rest of this config's Vertico/Corfu-based
completion UI rather than RefTeX's older pick-from-a-list interface.
It coexists with RefTeX rather than replacing it: RefTeX continues to
handle labels, cross-references, the table of contents, and
multi-file navigation exactly as configured in =ljs-config-latex.org=;
citar only takes over citation insertion.

=citar-latex-prompt-for-cite-style= defaults to t, so inserting a
citation still prompts for which macro to use (=\cite=, =\textcite=,
=\autocite=, and so on) each time -- the same everyday workflow as
RefTeX's =reftex-cite-format= keys (=C-m=, =t=, =a=, =p=...) below,
just with fuzzy completion for finding the reference itself.

#+end_src

#+begin_src emacs-lisp
(use-package citar
  :custom
  ;; Set to footcite rather than plain cite: this config's citation
  ;; style is footnotes-only (oscola), and the LaTeX template audit
  ;; found \footcite and hand-wrapped \footnote{\cite{}} mixed
  ;; through real documents inconsistently -- \footcite handles the
  ;; footnote punctuation itself and plays properly with
  ;; ibidtracker, so it's the one to default to. This now diverges
  ;; from RefTeX's own cite-format RET key in ljs-config-latex.org,
  ;; which still defaults to plain cite -- worth reconciling if that
  ;; RefTeX picker is still actually used day to day, but not done
  ;; here since it wasn't asked for.
  (citar-latex-default-cite-command "footcite")
  ;; citar-latex's own default list of citation commands, copied
  ;; verbatim from citar-latex.el, plus \citenourl (sussex-teaching.sty,
  ;; 17 Sept 2026) added to the second group -- the one requiring no
  ;; [Prenote]/[Postnote] prompts, since \citenourl only ever takes a
  ;; bare key list. Needed so citar's "Cite command:" prompt on C-c [
  ;; actually offers it (and inserts it with the right, arg-less shape)
  ;; rather than only accepting it if hand-typed. Overriding the whole
  ;; list rather than pushing onto it because `:custom' always sets a
  ;; literal value -- if citar-latex.el's own default list ever changes
  ;; upstream, this stops tracking it and needs updating by hand.
  (citar-latex-cite-commands
   '((("cite" "Cite" "citet" "Citet" "citep" "Citep" "parencite"
       "Parencite" "footcite" "footcitetext" "textcite" "Textcite"
       "smartcite" "Smartcite" "cite*" "parencite*" "autocite"
       "Autocite" "autocite*" "Autocite*" "citeauthor" "Citeauthor"
       "citeauthor*" "Citeauthor*" "citetitle" "citetitle*" "citeyear"
       "citeyear*" "citedate" "citedate*" "citeurl" "fullcite"
       "footfullcite" "notecite" "Notecite" "pnotecite" "Pnotecite"
       "fnotecite")
      . (["Prenote"] ["Postnote"] t))
     (("nocite" "supercite" "citenourl") . nil)))
  :hook
  ;; Wires citar into Corfu/Cape's in-buffer completion (see
  ;; ljs-config-completion.org): typing inside \cite{...} now offers
  ;; live completion candidates the same way any other capf source
  ;; does.
  (LaTeX-mode . citar-capf-setup)
  :config
  ;; Takes over the key RefTeX used for citation insertion. A plain
  ;; `local-set-key' from a LaTeX-mode-hook (the previous approach)
  ;; never actually won this: RefTeX turns itself on as a minor mode
  ;; (`reftex-mode'), and an active minor mode's keymap always takes
  ;; precedence over a major mode's local map for the same key --
  ;; regardless of hook order -- so RefTeX's own C-c [ ->
  ;; `reftex-citation' binding kept winning silently. Confirmed live:
  ;; C-c [ was popping RefTeX's "SELECT A CITATION FORMAT" picker
  ;; instead of citar. Rebinding the key directly inside
  ;; `reftex-mode-map' itself is what actually shadows it.
  (with-eval-after-load 'reftex
    (define-key reftex-mode-map (kbd "C-c [") #'citar-insert-citation)))
#+end_src

** Auto-categorizing Essential/Further from how a reading is cited

Agreed with Lindsay 17 Sept 2026, as part of the Essential/Further
reading-list design in =sussex-teaching.sty= (see the audit's
seminar-template-build notes): rather than typing a separate
=\addtocategory{essential|further}{KEY}= by hand after every
citation, the category is inferred automatically from *how* the
citation was just inserted, on the discipline Lindsay is committing
to going forward -- cite Essential readings in the body (=\footcite=
and friends), and reach for =nocite= (typed at the same "Cite
command:" prompt citar already shows on every =C-c [=) for
everything else. A real citation command means Essential; a bare
=nocite= means Further.

This only fires for a genuinely *new* citation -- the other branch of
=citar-latex-insert-citation= (adding another key onto an
already-open =\cite{...}= at point, rather than starting a fresh one)
never reaches the "Cite command:" prompt at all, so there's no
command to read there. That narrower case -- appending one more key
to a citation you already inserted -- still needs its own
=\addtocategory= added by hand; judged rare enough next to the
everyday "search and insert one reading" workflow not to be worth
chasing down a substitute signal for it.

*Correction, 17 Sept 2026, found on Lindsay's first real compile*:
=\addtocategory= turns out to be a preamble-only biblatex command --
calling it in the body throws "! LaTeX Error: Can be used only in
preamble" and aborts the compile (confirmed against biblatex's own
manual and its shipped example, =14-references-by-category.tex=,
which declares categories and calls =\addtocategory= together in the
preamble, never in the body). The first version of this advice
inserted the =\addtocategory= call right at point, next to the
citation -- wrong, and it broke Lindsay's very first real citation.
Fixed below: the call is now written into the document's preamble,
immediately before =\begin{document}=, while point stays exactly
where the citation was. `save-excursion' keeps this safe -- it holds
point as a marker, so inserting text earlier in the buffer doesn't
leave point in the wrong place afterwards.

#+begin_src emacs-lisp
(defvar ljs/citar-last-cite-command nil
  "Command most recently chosen at citar's \"Cite command:\" prompt.

Set as a side effect of advice on `citar-latex--select-command';
read by advice on `citar-latex-insert-citation' to decide which
Essential/Further category to auto-assign a citation just inserted.
Not meant to be set by hand.")

(advice-add 'citar-latex--select-command :filter-return
            (lambda (command)
              (setq ljs/citar-last-cite-command command)
              command))

(defun ljs/citar-insert-addtocategory (category keys)
  "Insert `\\addtocategory{CATEGORY}{KEYS}' into the preamble.

\\addtocategory is a preamble-only biblatex command, unlike \\cite or
\\nocite, so it cannot simply be inserted at point alongside a body
citation -- see this section's own commentary for how that mistake
was found. Searches for the buffer's own \\begin{document} and
inserts immediately before it, leaving point (wherever the calling
advice needs it to stay) untouched. Only handles a single-file
document with \\begin{document} in the same buffer -- one that
\\input/\\include's its content from elsewhere would need this called
from the master file's own buffer instead."
  (save-excursion
    (goto-char (point-min))
    (if (re-search-forward "^\\\\begin{document}" nil t)
        (progn
          (beginning-of-line)
          (insert (format "\\addtocategory{%s}{%s}\n" category keys)))
      (message "ljs-config: no \\begin{document} found in this buffer -- \\addtocategory{%s}{%s} not inserted, add it to the preamble by hand."
               category keys))))

(defun ljs/citar-auto-addtocategory (orig-fun keys &optional invert-prompt command)
  "Call `citar-latex-insert-citation', then auto-tag KEYS by category.

Essential/Further is inferred from how KEYS were just cited: a
plain \\nocite means Further, any real citation command (\\footcite,
\\cite, etc.) means Essential -- see this section's own commentary
for the discipline this assumes and the one case it doesn't cover.
The actual `\\addtocategory' call goes into the preamble, not next to
the citation -- see `ljs/citar-insert-addtocategory'."
  (let ((already-in-citation (citar-latex--macro-bounds)))
    (setq ljs/citar-last-cite-command nil)
    (prog1 (funcall orig-fun keys invert-prompt command)
      (when (and keys (not already-in-citation))
        (let* ((effective-command (or command
                                       ljs/citar-last-cite-command
                                       citar-latex-default-cite-command))
               (category (if (equal effective-command "nocite") "further" "essential")))
          (ljs/citar-insert-addtocategory category (string-join keys ",")))))))

(advice-add 'citar-latex-insert-citation :around #'ljs/citar-auto-addtocategory)
#+end_src

** citar-embark integration

Adds contextual actions -- open the attached PDF, open notes, open the
entry's URL/DOI -- on a citation key at point or in the minibuffer,
using Embark (already configured in =ljs-config-completion.org=)
rather than a bespoke keymap of its own.

#+begin_src emacs-lisp
(use-package citar-embark
  :after (citar embark)
  :config
  (citar-embark-mode))
#+end_src

** Shared bibliography export for collaborators (opt-in per document)

The master =Zotero.bib= auto-export (see "Where the =.bib= files
live" above) is Lindsay's own private working bibliography -- fine
for her own compiling, but a co-author without access to it can't
compile the same document independently. Rather than share the
whole master library, or rely on remembering a manual export step
before sending a draft round, this regenerates a paper-specific
=.bib= -- containing only the keys that document actually cites --
as a side effect of every compile, via =bibexport= (ships with most
TeX Live installs; checked defensively below, same "loads harmlessly
and says why" pattern as eglot and Matrix elsewhere in this config).
Written into the same directory as the document's own master =.tex=
file -- alongside =/Literature= and everything else already shared
with a collaborator via Dropbox -- so it just appears where a
co-author already looks, with nothing extra to send.

A per-document Local Variables toggle, not a hardcoded always-on
hook -- but as of Lindsay's own deliberate choice (13 Sept 2026),
=article-template.tex= itself now ships with =ljs-bib-export-shared:
t= already set, alongside its existing =TeX-engine= line, so this
runs by default on every new article created via =ljs/new-article=
(=C-c t a=), not only on papers explicitly flagged as collaborative.
The original design here had this off by default, opt-in per
document -- Lindsay considered that trade-off directly and chose
on-by-default instead, on the reasoning that the cost of running
=bibexport= against a document with nothing collaborative about it is
just a harmless regenerated =.bib= nobody needs, not a real problem
worth guarding against with an extra opt-in step every time. A
specific document can still turn it off individually, by setting
=ljs-bib-export-shared: nil= in that document's own Local Variables
(overriding the template's default the same way a document can pin
its own =TeX-engine= regardless of the template's):

: %%% Local Variables:
: %%% TeX-engine: luatex
: %%% ljs-bib-export-shared: t
: %%% End:

(single =%= per line in an actual =.tex= file, as AUCTeX itself
expects and as Lindsay's real templates already use -- the =%%%=
above is just this documentation's own generic illustration, not a
literal requirement.) Harmless if a co-author without this config
opens the same file in a plain Emacs: an unrecognised Local Variable
is just ignored (or, at most, a one-time "is this safe?" prompt they
can decline) -- it does nothing on their end either way.

Hooked onto the same =TeX-after-compilation-finished-functions= that
already refreshes the PDF pane after a recompile
(ljs-config-latex.org, "SyncTeX and PDF auto-refresh") -- one more
function added to that hook, not a separate mechanism, so the shared
=.bib= regenerates every time the document does, with nothing extra
to remember. Uses AUCTeX's own =TeX-master-file=/=TeX-master-directory=
to find the =.aux= file and place the output, rather than assuming
the visited buffer's own file name -- correct for a multi-file
document (=\input=/=\include=) where the master and the
currently-open buffer aren't the same file.

*Not yet tested*: =bibexport='s exact invocation for a biblatex-based
=.aux= (rather than plain BibTeX's) needs confirming against a real
installed copy (=bibexport --help=) and a real compile with real
citations before this is trusted -- flagged here rather than
assumed, per this file's own established practice of marking staged,
unverified work as such. The flags below (=-b= for biblatex mode,
=-o= for output) are a best-effort guess, not a confirmed reading of
bibexport's own documentation; if they're wrong, =bibexport='s own
exit code and output (captured into a =*bibexport*= buffer) will say
so immediately rather than fail silently -- that's the first real
test this needs, on Lindsay's own machine where TeX Live actually is.

#+begin_src emacs-lisp :tangle yes
(put 'ljs-bib-export-shared 'safe-local-variable #'booleanp)

(defun ljs/export-shared-bib (&optional _output-file)
  "Regenerate a paper-specific .bib for a document that has opted in.

Only runs when the current document's Local Variables set
`ljs-bib-export-shared' non-nil. Extracts just the entries this
document actually cites -- via `bibexport', into a .bib file named
and placed alongside the document's own master .tex file -- so a
collaborator can compile without needing Lindsay's own master
Zotero.bib. See this file's \"Shared bibliography export\" section
for the full design and the caveat on bibexport's exact flags.

Takes (and ignores) one argument -- the output file name -- because this is
hung on `TeX-after-compilation-finished-functions', which always calls its
functions with that argument. A zero-arg version of this function threw a
real `wrong-number-of-arguments' error on every single compile of every
document, whether or not `ljs-bib-export-shared' was set -- the crash
happens at the call site, before the body (and its own opt-in check) ever
runs."
  (when (bound-and-true-p ljs-bib-export-shared)
    (if (not (executable-find "bibexport"))
        (message "ljs-config: bibexport not found on PATH -- shared .bib not regenerated for this document.")
      (let* ((dir (TeX-master-directory))
             (base (TeX-master-file nil t))
             (aux-file (expand-file-name (concat base ".aux") dir))
             (bib-file (expand-file-name (concat base ".bib") dir)))
        (if (not (file-exists-p aux-file))
            (message "ljs-config: no .aux file yet for shared .bib export -- compile once first.")
          (let ((exit-code (call-process "bibexport" nil "*bibexport*" nil
                                          "-b" "-o" bib-file aux-file)))
            (if (zerop exit-code)
                (message "ljs-config: shared .bib regenerated (%s)." bib-file)
              (message "ljs-config: bibexport failed (exit %d) -- see *bibexport* buffer." exit-code))))))))

(add-hook 'TeX-after-compilation-finished-functions #'ljs/export-shared-bib)
#+end_src
