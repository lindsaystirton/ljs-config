** Make shift-enter to a lot in ESS.
 Use shift-enter to split window & launch R (if not running), execute
 highlighted region (if R running & area highlighted), or execute
 current line (and move to next line, skipping comments). Nice. See
 http://www.emacswiki.org/emacs/EmacsSpeaksStatistics,
 FelipeCsaszar. Adapted to double the window with when R is opened in
 a frame on the right.
 
#+name: ess-shift-enter
#+begin_src emacs-lisp
(defun my-ess-start-R ()
  "Start R and split the window horizontally, doubling the frame width."
  (interactive)
  (or (assq 'inferior-ess-mode
            (mapcar 
              (lambda (buff) (list (buffer-local-value 'major-mode buff)))
              (buffer-list)))
   (progn
     (delete-other-windows)
     (setq w1 (selected-window))
     (setq w1name (buffer-name))
     (setq w2 (split-window w1 nil t))
     (R)
     (set-window-buffer w2 "*R*")
     (set-window-buffer w1 w1name)
     (ljs/frame-remember-and-double)))) ; Double the frame width, via ljs-config-appearance.org
  (defun my-ess-eval ()
    (interactive)
    (my-ess-start-R)
    (if (and transient-mark-mode mark-active)
	(call-interactively 'ess-eval-region)
      (call-interactively 'ess-eval-line-and-step)))
  (add-hook 'ess-mode-hook
	    (lambda()
	       (local-set-key [(shift return)] 'my-ess-eval)))
  (add-hook 'inferior-ess-mode-hook
	    (lambda()
	       (local-set-key [C-up] 'comint-previous-input)
	       (local-set-key [C-down] 'comint-next-input))) 
  (require 'ess-site)
#+end_src

** Restore Original Frame Dimensions on quitting R
Following the behaviour of my-ess-start-r, the following code makes
sure that the window dimensions revert with R is killed.

NOTE (§25/§27 consolidation): this was called
=my-restore-original-dimensions=, the *exact same name* as an
unrelated function in ljs-config-latex.org. Emacs Lisp functions
aren't file-scoped, so whichever file loaded later (this one, per
the load order in ljs-config.org) silently won and overrode LaTeX's
version everywhere -- a live conflict, not just a stylistic
duplicate. Renamed to `ljs/ess-restore-or-restart-R' to end that
collision.

Separately: despite the section heading, this was never actually
wired to fire when R is killed -- no `kill-buffer-hook' on the *R*
buffer called it, unlike the equivalent PDF setup in
ljs-config-latex.org. Now fixed below, but *not* by hooking
`ljs/ess-restore-or-restart-R' itself: a `kill-buffer-hook' runs with
the buffer being killed as `current-buffer', so if that function ran
as the hook, its own "*R*" check would always match the very buffer
being killed and take the "restart R" branch -- meaning killing *R*
would immediately relaunch it instead of ever restoring anything.
`ljs/ess-restore-or-restart-R' is kept as-is, available to call
manually from elsewhere (e.g. from the source buffer, to either
restart R or just restore, depending where you are when you call
it); the automatic kill-buffer-hook below calls the shared
=ljs/frame-restore-original-dimensions= directly instead, which is
the behaviour the section heading actually describes.

#+name: ess-restore-frame-dimensions
#+begin_src emacs-lisp
(defun ljs/ess-restore-or-restart-R ()
  "Restore the pre-R frame width, or restart R if called from *R* itself."
  (interactive)
  (if (string-match-p "\\*R\\*" (buffer-name (current-buffer)))
      (my-ess-start-R)
    (ljs/frame-restore-original-dimensions)))

(add-hook 'inferior-ess-mode-hook
          (lambda ()
            (add-hook 'kill-buffer-hook
                      #'ljs/frame-restore-original-dimensions nil 'local)))
#+end_src


** Add a Keyboard Shortcut for the Pipe Operator

Assignment in ESS is shift-minus; by extension we'll use M-shift-minus for inserting the `%>%` operator.

(defun my_pipe_operator ()
  "R/ESS %>% operator"
  (interactive)
  (just-one-space 1)
  (insert "%>%")
  (reindent-then-newline-and-indent))
(define-key ess-mode-map (kbd "M-_") 'my_pipe_operator)
(define-key inferior-ess-mode-map (kbd "M-_") 'my_pipe_operator)

** Install and Configure Company-Stan

NOTE: this has been through a few iterations, and the real bug was
misdiagnosed each time. First, gating on =:after stan-mode= and then
=:after company= both produced "Symbol's function definition is void:
company-stan" -- this was assumed to be a load-timing problem, "fixed"
by tying the completion-at-point-functions registration to actually
entering a stan-mode buffer (via stan-mode-hook) instead of
package-load time. That deferred *when* the error surfaced but not
*whether* it did: the same void-function error still occurred, now
triggered by Corfu the first time it tried to complete in a .stan
buffer rather than at startup. The actual root cause, found by reading
company-stan.el directly: the package's own completion backend
function is named =company-stan-backend=, not =company-stan= -- there
is no function called =company-stan= anywhere in the package (only
=company-stan-backend= and the setup convenience function
=company-stan-setup=). Every prior fix attempt was solving a timing
problem that didn't exist while leaving the actual wrong-symbol bug in
place. Since Company itself was retired in favour of Corfu (see
ljs-config-completion.org) and Stan has no LSP server,
=company-stan-backend= is bridged into the standard
completion-at-point-functions mechanism via Cape's
=cape-company-to-capf=, registered buffer-locally so it only applies
inside stan-mode buffers, not globally.

#+name: ljs-config-company-stan
#+begin_src emacs-lisp 
  (use-package company-stan
    :after stan-mode
    :config
    (add-hook 'stan-mode-hook
              (lambda ()
                (add-hook 'completion-at-point-functions
                          (cape-company-to-capf #'company-stan-backend)
                          nil t))))
#+end_src

** Org-babel execution (ob-stan)

No package ships an ob-stan for a modern Emacs/Org -- confirmed (see
the audit, §55): not bundled with Org itself (unlike R), not in the
actively-maintained org-contrib, not on MELPA. The only one that ever
existed lived in the long-retired =org-plus-contrib= bundle. This
reimplements it from that original's own design (read directly from
its source, not guessed), because the design is already right for
what Stan actually needs: a Stan block on its own has no data or
sampler settings, so executing one can never sample a model -- it can
only produce a model artifact (a =.stan= file, or a CmdStan-compiled
executable) for a /following/ R (rstan) or shell (CmdStan CLI) block
to actually run. A =:file= header argument is therefore required,
the same convention =ob-ditaa=/=ob-dot=/=ob-gnuplot= use for their own
file-producing blocks -- the function itself returns nil and lets
org-babel's standard =:results file= handling build the
=[[file:...]]= link, which is what makes the result usable as a
variable in the next block down. One improvement over the original:
this actually checks whether the CmdStan compile succeeded, rather
than silently leaving no executable behind on failure.

#+name: ljs-config-ob-stan
#+begin_src emacs-lisp
  (defcustom org-babel-stan-cmdstan-directory
    (car (last (sort (file-expand-wildcards
                       (expand-file-name "~/.cmdstan/cmdstan-*"))
                      #'string<)))
    "CmdStan installation directory used by ob-stan to compile Stan blocks.

  Auto-detected from ~/.cmdstan/cmdstan-* (the highest-numbered version,
  if more than one is installed) -- override directly if that picks the
  wrong one, CmdStan lives somewhere else, or you'd rather ob-stan just
  dump `.stan' files without compiling (set to nil)."
    :group 'org-babel
    :type '(choice (directory :tag "Compilation directory")
                   (const :tag "Dump to a file" nil)))

  (defvar org-babel-default-header-args:stan
    '((:results . "file"))
    "Stan blocks produce a file artifact, not a printed value.")

  (defun org-babel-execute:stan (body params)
    "Generate a Stan model file (and optionally compile it) from BODY.

  A :file header argument is required. When
  `org-babel-stan-cmdstan-directory' is set and FILE has no `.stan'
  extension, BODY is saved to FILE.stan and compiled via CmdStan's own
  `make' into an executable at FILE; otherwise BODY is written to FILE
  verbatim. Either way this never samples the model -- see the audit,
  §59, for why that's a following R/rstan or shell/CmdStan-CLI block's
  job, not this one's."
    (let ((file (expand-file-name
                 (or (cdr (assq :file params))
                     (user-error "Set a :file header argument to execute a Stan block")))))
      (if (or (not org-babel-stan-cmdstan-directory)
              (string-match-p "\\.stan\\'" file))
          (with-temp-file file (insert body))
        (with-temp-file (concat file ".stan") (insert body))
        (let ((default-directory org-babel-stan-cmdstan-directory)
              (buf (get-buffer-create "*ob-stan-compile*")))
          (with-current-buffer buf (erase-buffer))
          (unless (zerop (call-process "make" nil buf t file))
            (pop-to-buffer buf)
            (error "CmdStan compile failed for %s -- see *ob-stan-compile*" file))))
      nil))
#+end_src
