** Startup

Basic setting preferences, including size and positioning of emacs frames.

#+end_src

#+begin_src emacs-lisp 
 (use-package emacs :straight nil
  :config
  (setq inhibit-startup-message t)
  (add-to-list 'initial-frame-alist '(top . 0))
  (add-to-list 'initial-frame-alist '(left . 0))
  (scroll-bar-mode -1)
  (tool-bar-mode -1)
  (tooltip-mode -1)
  (set-fringe-mode 10)
  (setq visible-bell t)
  (electric-indent-mode 1))

The initial frame's width and height used to be hardcoded here (85
columns x 54 rows) -- tuned specifically to Lindsay's 13.3-inch
MacBook screen, and wrong on the office iMac's larger display or any
other machine (see the audit, §41). Sized dynamically instead, the
same way `ljs/frame-double-width' below sizes a split-right window:
from the real screen, via `frame-monitor-workarea', rather than a
guess. This has to run from `window-setup-hook' rather than going
into `initial-frame-alist' directly, since there's no frame yet to
ask `frame-monitor-workarea' about until the first one exists.

#+name: ljs-config-appearance-dynamic-initial-size
#+begin_src emacs-lisp
(defvar ljs/frame-default-width-fraction 0.47
  "Fraction of the monitor's workarea width the frame sits at
normally -- at startup, and whenever a doubled or widened pane
closes back down. Just under half: comfortably fits an 80-column
buffer with room to spare on any screen size, while leaving room
for `ljs/frame-double-width' to double it without the result
running flush against the monitor's physical edge (exactly half
would do that). One named constant rather than the same literal
0.47 sitting in both `ljs/frame-set-initial-size' below and
`ljs/frame-restore-original-dimensions' further down -- see the
audit's Claude Code frame-doubling discussion for why the latter
needed it too.")

(defun ljs/frame-set-initial-size (&optional frame)
  "Size the initial frame from the real screen, once it exists.
See `ljs/frame-default-width-fraction' for why the width fraction is
what it is. 90% of the available screen height: `frame-monitor-workarea'
already excludes the menu bar and Dock on macOS, so this fills most
of the screen vertically with a little headroom to spare, well
short of ever overlapping the Dock."
  (let ((frame (or frame (selected-frame))))
    (when (display-graphic-p frame)
      (let* ((workarea (frame-monitor-workarea frame))
             (mon-width-px (nth 2 workarea))
             (mon-height-px (nth 3 workarea))
             (cols (max 80 (floor (* ljs/frame-default-width-fraction mon-width-px) (frame-char-width frame))))
             (rows (max 40 (floor (* 0.9 mon-height-px) (frame-char-height frame)))))
        (set-frame-size frame cols rows)))))

(add-hook 'window-setup-hook #'ljs/frame-set-initial-size)
#+end_src


** Fonts

This used to live in =early-init.el=, on the theory that setting the
font before the frame is created would avoid a visible flash of the
wrong font followed by a resize. In practice that broke font
selection outright: =x-list-fonts= (and so =font-existsp=, below)
isn't reliable that early in startup on the macOS/NS build of
Emacs -- it was silently returning nil for *every* font, including
ones definitely installed (Menlo included), so the whole
=cond= fell through and Emacs was left showing its own untouched
default face rather than any of the fonts below. See the audit,
§32.

Moving it back here means the old flash-then-resize on startup
returns -- that's the normal, longstanding Emacs experience prior to
this rebuild, not a regression -- in exchange for the font selection
actually working.

Check the availability of a some default fonts, in order of
preference. The first of these alternatives to be found is set as
the default font, together with a base size. If none of the
preferred fonts is found, nothing happens and Emacs carries on with
the default setup. You can reorder or replace the options here with
the names of your preferred choices.

#+begin_src emacs-lisp
(defun font-existsp (font)
  "Check to see if the named FONT is available."
  (if (null (x-list-fonts font))
      nil t))

;; Set default font. First one found is selected.
(cond
 ((eq window-system nil) nil)
 ((font-existsp "IBM Plex Mono Text")
  (set-face-attribute 'default nil :height 141 :font "IBM Plex Mono Text"))
 ((font-existsp "Input Mono Compressed")
  (set-face-attribute 'default nil :height 141 :font "Input Mono Compressed"))
 ((font-existsp "PragmataPro")
  (set-face-attribute 'default nil :height 141 :font "PragmataPro"))
 ((font-existsp "Source Code Pro")
  (set-face-attribute 'default nil :height 141 :font "Source Code Pro"))
 ((font-existsp "Menlo")
  (set-face-attribute 'default nil :height 141 :font "Menlo"))
 ((font-existsp "Consolas")
  (set-face-attribute 'default nil :height 141 :font "Consolas"))
 ((font-existsp "Inconsolata")
  (set-face-attribute 'default nil :height 141 :font "Inconsolata"))
 ((font-existsp "Envy Code R")
  (set-face-attribute 'default nil :height 141 :font "Envy Code R")))
#+end_src

** Visual polish

Four small, independently-toggleable upgrades to how editing *feels*
day to day, batched together after one round of "what's worth
turning on" discussion rather than spread across four separate
sessions: smooth pixel scrolling, breathing room around the frame
edges and mode line, ligatures for common code glyph sequences, and
a pulse on the current line after scrolling or jumping somewhere, so
the cursor is easier to find again. A fifth candidate discussed
alongside these -- a floating completion palette -- was deliberately
skipped. None of the four touch any keybinding or workflow; each is
independently toggleable (`M-x <name>-mode`, or just commenting out
its block here) if it doesn't earn its keep in practice.

*** Smooth scrolling

Built into Emacs 29+ (`pixel-scroll-precision-mode`) -- nothing for
straight.el to fetch. Replaces the old line-at-a-time mouse-wheel/
trackpad scroll with pixel-smooth motion that tracks the actual
scroll gesture.

Deliberately narrow in what it changes: this only touches
wheel/trackpad scrolling. Everything keyboard-driven -- `C-v`/`M-v`,
`C-l` to recenter, which is most of what actually gets used day to
day in Org/AUCTeX/magit -- lands on exactly the same line boundaries
as before, untouched. The one real rough edge: very large or
heavily-decorated buffers (a big Org table, a `pdf-tools` buffer)
can judder slightly at the very top/bottom edge while it settles
mid-scroll, and it occasionally sits a little oddly with things that
expect a clean line boundary (`recenter`, `scroll-margin`) --
cosmetic quirks only, and reversible in one `M-x
pixel-scroll-precision-mode` with no cleanup if it ever feels wrong.

#+name: ljs-config-appearance-smooth-scrolling
#+begin_src emacs-lisp
(use-package emacs
  :straight nil
  :config
  (pixel-scroll-precision-mode 1))
#+end_src

*** Spacious padding

Prot's `spacious-padding`: pixel-level breathing room around window
edges, the header/tab line, and the mode-line divider -- purely
cosmetic, no change to any command or binding. Designed by the same
author as `modus-themes` and meant to be used alongside it; adds
padding around the mode line rather than replacing it, so it sits
fine next to `doom-modeline` too. Widths set explicitly below (Prot's
own suggested starting values) rather than left at the package
default, so the actual numbers are visible and adjustable here rather
than buried in the package's own defcustom.

#+name: ljs-config-appearance-spacious-padding
#+begin_src emacs-lisp
(use-package spacious-padding
  :config
  (setq spacious-padding-widths
        '( :internal-border-width 15
           :header-line-width 4
           :mode-line-width 6
           :tab-width 4
           :right-divider-width 15
           :scroll-bar-width 8
           :fringe-width 8))
  (spacious-padding-mode 1))
#+end_src

*** Ligatures

`ligature.el` (mickeynp), set up here for `prog-mode` and everything
derived from it -- so R/ESS, Python, Stan, and Emacs Lisp buffers,
but not Org or LaTeX prose (`LaTeX-mode` doesn't derive from
`prog-mode`, deliberately not touched here). Safe regardless of which
font from the Fonts section above ends up loaded: ligature.el doesn't
draw its own glyphs, it asks Emacs's font-shaping backend to compose
each matched character sequence as a unit and let the *font's* own
OpenType ligature table substitute a glyph if it has one for that
exact sequence -- if the loaded font has no such glyph (true of most
of the list in the Fonts section), the sequence just renders as
plain adjacent characters, exactly as before. No breakage either way.
Of the fonts checked above, `PragmataPro` is the one genuinely built
with an extensive ligature set; the others will likely no-op
silently.

The specific sequence list below is a practical subset (arrows,
comparisons, comment markers, `::`/`:=`) rather than the full
upstream example list -- deliberately skipping the handful of
backslash-heavy entries in that list, since they're not worth the
risk of a hand-typed escaping mistake for symbols Lindsay's actual
languages don't use.

#+name: ljs-config-appearance-ligatures
#+begin_src emacs-lisp
(use-package ligature
  :config
  (ligature-set-ligatures 'prog-mode
                          '("->" "->>" "-->" "<-" "<--" "<->"
                            "=>" "==" "===" "!=" "!==" "<=" ">="
                            "&&" "||" "::" ":=" "|>" "<|" "++" "--"
                            "**" "..." ".." "//" "///" "/*" "*/"
                            "<<" ">>" "<<=" ">>=" "~>" "<~"))
  (global-ligature-mode t))
#+end_src

*** Pulsar

Prot's `pulsar`: pulses the current line briefly after scrolling,
switching windows, or otherwise jumping somewhere in the buffer, so
the cursor doesn't need to be hunted for after the jump. Purely
visual feedback, no change to any command's behaviour.
`pulsar-global-mode` covers its own curated list of built-in
navigation commands; the two `next-error-hook` additions extend that
to compile/grep/occur-style "jump to the next match" navigation,
which isn't on that built-in list but comes up constantly in this
config's LaTeX-compile and R workflows.

#+name: ljs-config-appearance-pulsar
#+begin_src emacs-lisp
(use-package pulsar
  :config
  (setq pulsar-pulse t)
  (setq pulsar-delay 0.05)
  (setq pulsar-iterations 10)
  (pulsar-global-mode 1)
  (add-hook 'next-error-hook #'pulsar-pulse-line)
  (add-hook 'next-error-hook #'pulsar-recenter-top))
#+end_src

** PDF VIew

The pdf-tools packages provides an emacs pdf viewer that replaces the standard docview programme. Getting it to compile on MacOS was not straighforward, but the following seemed to solve any problems. 

*** Reinstall Dependencies

  Run the following command in your terminal to reinstall dependencies:

  #+BEGIN_SRC shell :tangle no
  brew reinstall cairo poppler glib libpng
  #+END_SRC

*** Open Emacs in Terminal/iTerm2

  Launch Emacs using the command line with the following command:

  #+BEGIN_SRC shell :tangle no
  /Applications/Emacs.app/Contents/MacOS/Emacs
  #+END_SRC

*** Verify pdfinfo Path

  Ensure that the correct filepath to `pdfinfo` is specified. You can do this by checking the `pdf-info-epdfinfo-program` variable in Emacs. Update the path if necessary.

  Example:
  #+BEGIN_SRC emacs-lisp :tangle no
  (setq pdf-info-epdfinfo-program "/path/to/pdfinfo")
  #+END_SRC

  Make sure to replace "/path/to/pdfinfo" with the actual path to your `pdfinfo` executable.

*** Restart Emacs

  After making changes, restart Emacs to apply the configuration.
  

=exec-path-from-shell= itself now lives much earlier, right after
the straight.el bootstrap in =ljs-config.org= -- it has to run
before anything that might shell out to a Homebrew tool during its
own package installation, which turned out to include things loaded
well before this file (see the audit, §43).

#+begin_src emacs-lisp
(use-package pdf-tools
  :custom
  (pdf-tools-handle-upgrades t) ;; don't prompt on every epdfinfo version bump
  ;; pdf-view.el's own top-level code (not doom-modeline's) unconditionally
  ;; probes whether the current font set can display two specific unicode
  ;; glyphs (a print/eject symbol and a crescent moon, for its own
  ;; mode-line lighter) every single time pdf-tools loads -- which, since
  ;; this use-package block has no :defer, is every startup. That font
  ;; probe (char-displayable-p) is the exact call crashing Emacs outright
  ;; (EXC_BAD_ACCESS/SIGABRT, a pointer-authentication failure -- real
  ;; memory corruption, not just a normal "no font found" result) -- see
  ;; the audit, §57. pdf-view.el's own author anticipated this could be
  ;; slow/risky and ships this off-switch for exactly that reason; setting
  ;; it nil skips the probe (and the mode-line lighter) entirely.
  (pdf-view-use-unicode-ligther nil)
  :config
  ;; Homebrew's zlib/poppler are "keg-only" and won't be found by
  ;; pkg-config without this, which pdf-tools-install needs the first
  ;; time it builds the epdfinfo server (or after an upgrade). Uses
  ;; Homebrew's own stable `opt/' symlinks rather than a specific
  ;; Cellar version, and HOMEBREW_PREFIX rather than a hardcoded
  ;; /opt/homebrew, so this doesn't need updating on every package
  ;; bump or break on an Intel Mac. (This used to be duplicated, with
  ;; a stale versioned Cellar path, in ljs-config-latex.org -- see
  ;; the audit.)
  (let ((brew (or (getenv "HOMEBREW_PREFIX") "/opt/homebrew")))
    (setenv "PKG_CONFIG_PATH"
            (concat brew "/opt/zlib/lib/pkgconfig:"
                    brew "/lib/pkgconfig:"
                    brew "/opt/poppler/lib/pkgconfig:"
                    "/opt/X11/lib/pkgconfig:/opt/X11/share/pkgconfig")))

  ;; Install pdf-tools
  (pdf-tools-install)
  (setq org-pdftools-command (or (executable-find "pdfinfo") "pdfinfo"))

  ;; Set pdf-tools as the default PDF viewer
  (setq-default pdf-viewer 'pdf-tools)

  ;; Ensure that pdf-tools is used for all PDF files
  (add-to-list 'auto-mode-alist '("\\.pdf\\'" . pdf-view-mode)))
#+end_src

* Splitting frames

I found the idea and code for this on a [[https://christiantietze.de/posts/2022/02/split-and-resize-frame/][blog post by Christian
Tietze]]. Basically douples the width of the window when splitting the
frame vertically. The problem with the original code is that if you closed the right frame, the window retained the same dimenions. This version retains the frame width and reduces the window size accordingly.

This is also the single canonical home for frame-doubling/restoring
logic used everywhere else in the config -- LaTeX compilation
(=ljs-config-latex.org=), starting R (=ljs-config-stats.org=), and
opening a PDF, a Markdown live-preview in eww, or a Claude Code
session (all three registered below, via =display-buffer-alist=,
rather than each having its own copy). Previously this was
reimplemented four separate times across four files with two
different naming conventions; see the audit, §11C/§25. Claude Code
(=ljs-config-claude-code.org=) reuses this deliberately, on
Lindsay's own explicit instruction -- same behaviour as PDF/eww, not
a new one built to match.

#+name: ljs-config-appearance-split-right-resize
#+begin_src emacs-lisp
(defvar ljs/original-frame-width nil
  "Variable to store the original frame width.")

(defun ljs/frame-double-width (&optional frame)
   (let* ((current_width (frame-pixel-width frame))
          (monitor_width (nth 2 (frame-monitor-workarea frame)))
          (double_width (min monitor_width
                             (* 2 current_width))))
       (set-frame-width frame double_width nil t)))

(defun ljs/frame-remember-and-double (&optional frame)
  "Remember FRAME's current width in `ljs/original-frame-width', then double it.
This is the shared \"about to show something in a split-right
window\" step -- see the call sites in ljs-config-latex.org,
ljs-config-stats.org, and `ljs/display-buffer-doubled-right' below."
  (setq ljs/original-frame-width (frame-pixel-width frame))
  (ljs/frame-double-width frame))

(defun ljs/frame-set-width-fraction (fraction &optional frame)
  "Set FRAME's width to FRACTION of its monitor's workarea width."
  (let* ((frame (or frame (selected-frame)))
         (monitor-width (nth 2 (frame-monitor-workarea frame))))
    (set-frame-width frame (floor (* fraction monitor-width)) nil t)))

(defun ljs/frame-remember-and-widen (&optional frame)
  "Remember FRAME's current width, then widen it to 80% of the monitor.
A second \"about to do some focused work\" step, sibling to
`ljs/frame-remember-and-double' above but different in kind: this
sets an absolute target width (80% of the monitor) rather than
doubling whatever width the frame already happens to be, since it's
meant for opening Matrix, mail, or the inbox from ordinary daily
use, not for a split-right pane next to the current buffer. Shares
`ljs/original-frame-width' and the `C-x 1'-bound
`ljs/frame-restore-original-dimensions' restore step with the
doubling mechanism above -- there's only one remembered width at a
time, so restore before switching to a different focused task (or
before opening a PDF/R/eww split) if the two are ever used back to
back, rather than assuming the very first original width is still
there to go back to. See the call sites in
ljs-config-communications.org, ljs-config-email.org, and
ljs-config-org.org.

Deliberately widen-only for now: closing Matrix/mail/the inbox
doesn't auto-shrink the frame back the way a doubled split-right
PDF/R/eww pane does on `q'/`C-x 0' (see the audit, §30/§46) --
those all create a specific new *window* to tag and watch for;
these three don't. Use `C-x 1' to shrink back manually until/unless
that's worth designing properly."
  (let ((frame (or frame (selected-frame))))
    (setq ljs/original-frame-width (frame-pixel-width frame))
    (ljs/frame-set-width-fraction 0.8 frame)))

(defun ljs/frame-restore-original-dimensions (&optional keep-current-window)
  "Restore the frame to its normal working width.
Also closes any extra windows the split created, unless
KEEP-CURRENT-WINDOW is non-nil (interactively, with a prefix
argument). This is the shared restore step used by the PDF, R,
Markdown/eww, and Claude Code call sites.

Recomputes `ljs/frame-default-width-fraction' fresh from the real
screen every time, via `ljs/frame-set-width-fraction', the same way
`ljs/frame-set-initial-size' does at startup -- rather than replaying
whatever `ljs/original-frame-width' happened to record just before
the last doubling/widening, which is only correct if nothing else
touched the frame's width in between. That assumption breaks in a
real, reachable way: only one width is ever remembered at a time
(this file's own long-standing note on the Matrix/mail/inbox widen
case), so opening a second doubled or widened pane on top of one
that's still open overwrites the first pane's remembered value with
the (already doubled/widened) current one -- closing either
afterward then restores to that wrong intermediate width, not the
frame's actual normal size. Found via Lindsay reporting exactly this
after closing a Claude Code session -- recomputing the target
fraction directly is immune to that whole class of drift, whereas
replaying a remembered number never was. `ljs/original-frame-width'
and the two `ljs/frame-remember-and-*' functions that set it are
left in place (harmless bookkeeping, not read by anything else) --
this function simply no longer reads it."
  (interactive "P")
  (unless keep-current-window
    (delete-other-windows))
  (ljs/frame-set-width-fraction ljs/frame-default-width-fraction (selected-frame)))

(defun ljs/split-right-and-resize-frame ()
  (interactive)
  (split-window-right)
  (ljs/frame-remember-and-double))

(defun ljs/display-buffer-doubled-right (buffer alist)
  "Show BUFFER in a new window to the right, after doubling the frame.
A `display-buffer-alist' action function -- registered below for
PDF buffers, the Markdown live-preview's eww buffer, and Claude Code
session buffers, so there's one canonical place for this rather
than a copy per consumer. Originally lived in ljs-config-org.org as
`ljs/display-pdf-to-right', PDF-only.

The window this creates is tagged with the `ljs/doubled-frame'
window parameter, so the `quit-window'/`delete-window' advice below
can notice when it goes away and restore the frame -- see the audit,
§30, on why a plain `kill-buffer-hook' (as used for PDF/R elsewhere
in this config) only catches half the ways this window can close."
  (ljs/frame-remember-and-double (window-frame (selected-window)))
  (let ((window (display-buffer-in-direction
                 buffer
                 (append alist '((direction . right) (window-width . 0.5))))))
    (when window
      (set-window-parameter window 'ljs/doubled-frame t))
    window))

(add-to-list 'display-buffer-alist '("\\.pdf\\'" . (ljs/display-buffer-doubled-right)))
(add-to-list 'display-buffer-alist '("\\`\\*eww\\*\\'" . (ljs/display-buffer-doubled-right)))
;; Claude Code (claude-code.el, ljs-config-claude-code.org) names its
;; vterm buffers "*claude:/path:instance-name*" -- one instance per
;; project/directory, so this matches on the fixed "*claude:" prefix
;; only, not a full buffer-name match like eww's (which never varies).
(add-to-list 'display-buffer-alist '("\\`\\*claude:" . (ljs/display-buffer-doubled-right)))

(global-set-key (kbd "C-x 3") 'ljs/split-right-and-resize-frame)
(global-set-key (kbd "C-x 1") 'ljs/frame-restore-original-dimensions)

;; Closing the *window* `ljs/display-buffer-doubled-right' created --
;; `q' (pdf-tools' and eww's own binding, `quit-window') or `C-x 0'
;; (`delete-window') -- without killing its buffer used to leave the
;; frame stuck doubled, since only a `kill-buffer-hook' was wired up
;; (PDF: ljs-config-latex.org; R: ljs-config-stats.org). Advising
;; both functions, rather than adding a third bespoke hook, covers
;; PDF and eww uniformly with the same mechanism. See the audit, §30.
(defun ljs/window-tagged-doubled-p (window)
  "Non-nil if WINDOW carries the `ljs/doubled-frame' parameter."
  (and (window-live-p window)
